## 1. Лабораторная №2: Юнит-тестирование в Spring Boot с JUnit 5 и Mockito

Эта работа посвящена **юнит-тестированию** — технике тестирования, при которой **отдельные компоненты** (модули, классы, методы) программного приложения проверяются **изолированно**.

| Инструмент                   | Сущность и назначение                                                                                                                                                                   |
| :--------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **JUnit 5**                  | Популярный фреймворк для **тестирования Java**. Предоставляет аннотации (`@Test`, `@BeforeEach`) для определения тестовых методов и классов.                                            |
| **Mockito**                  | Фреймворк для создания **мок-объектов (заглушек)** зависимостей (например, репозитория или сервиса). Используется для **изоляции** тестируемого компонента от его реальных зависимостей |
| **AssertJ**                  | Библиотека, предоставляющая **выразительные утверждения** (`assertThat(...).isEqualTo(...)`) для более четкого и читаемого кода проверок ожидаемых результатов.                         |
| **Spring Boot Starter Test** | Зависимость, включающая в себя все основные библиотеки для тестирования Spring Boot: **JUnit**, **Mockito**, **Hamcrest**, **AssertJ**.                                                 |

### Основные аннотации и концепции

* **`@DataJpaTest`**: Используется для тестирования **JPA репозиториев**. Загружает только минимальный контекст Spring, связанный с базой данных (не загружает `@Service`, `@Controller` и т.д.).
* **`@WebMvcTest`**: Используется для тестирования **Spring MVC контроллеров**. Загружает только контекст, связанный с MVC, и часто используется с **MockMvc**.
* **MockMvc**: Класс, позволяющий выполнять **виртуальные HTTP-запросы** к контроллерам без запуска полноценного HTTP-сервера.
* **BDD-стиль Mockito**: Используется для настройки поведения мок-объектов:
    *`given()`: Настройка предварительного условия (что мок должен вернуть).
    * `verify()`: Проверка, что метод мок-объекта был вызван.
* **`@Rollback(true)`**: Указывает, что транзакция должна быть **откачена** после завершения тестового метода, чтобы не влиять на состояние базы данных.

## 3. Лабораторная №4: Flyway

Эта работа знакомит с инструментом для **управления миграциями баз данных**.

* [cite_start]**Flyway**: Универсальный инструмент с открытым исходным кодом для **миграции баз данных и управления схемами**[cite: 2533].
* [cite_start]**Назначение**: Решает проблемы ручных миграций (несогласованность, ошибки), автоматизируя задачи и обеспечивая **версионный контроль** изменений схемы[cite: 2532, 2534].
* [cite_start]**Принцип работы**: Flyway автоматически обнаруживает **миграционные скрипты** (обычно SQL-файлы, например, `V1__create_table.sql`) в определенной директории (`db/migration`) и применяет их к базе данных[cite: 2598].
* [cite_start]**Таблица метаданных**: Flyway отслеживает все примененные миграции в специальной таблице `flyway_schema_history`[cite: 2599]. Это гарантирует, что каждый скрипт будет выполнен только один раз и в правильном порядке.
* [cite_start]**Интеграция**: Flyway бесшовно интегрируется со Spring Boot, запуская миграции автоматически при старте приложения[cite: 2623].

## 4. Лабораторная №5: Swagger UI / OpenAPI

Эта работа посвящена **документированию и тестированию REST API**.

* [cite_start]**Swagger (Спецификация OpenAPI)**: Набор правил и спецификаций, которые являются **стандартом** для описания RESTful API в **машиночитаемом формате**[cite: 2878, 2879]. [cite_start]Помогает документировать API[cite: 2855].
* [cite_start]**Swagger UI**: **Пользовательский интерфейс**, который принимает спецификацию OpenAPI и генерирует **динамический, интерактивный интерфейс документации**[cite: 2877, 2880].
* **Ключевые возможности Swagger UI**:
    * [cite_start]**Интерактивная документация**: Отображает подробную информацию о конечных точках (URL, методы, параметры)[cite: 2881].
    * [cite_start]**Тестирование API**: Позволяет разработчикам **отправлять запросы** к API прямо из веб-браузера для быстрого тестирования и понимания работы конечных точек[cite: 2882].
* [cite_start]**Интеграция со Spring Boot**: Обычно достигается добавлением соответствующих зависимостей и настройкой в файле конфигурации[cite: 2893].

## 5. Лабораторная №6: @FeignClient

Эта работа посвящена **межсервисной коммуникации** в архитектуре микросервисов.

* [cite_start]**@FeignClient (Spring Cloud OpenFeign)**: Аннотация Spring, предназначенная для **декларативного** и упрощенного **взаимодействия между микросервисами** (клиент-серверная связь)[cite: 3363, 3373].
* **Назначение**: Абстрагирует уровень HTTP-клиента. [cite_start]Вместо написания шаблонного кода для HTTP-вызовов, разработчик просто определяет **Java-интерфейс**, аннотированный `@FeignClient`, а Spring автоматически генерирует его реализацию для выполнения REST-вызовов[cite: 3370, 3374].
* **Ключевые преимущества**:
    * [cite_start]**Декларативный подход**: Вы просто описываете, какой сервис и метод вызвать, не занимаясь низкоуровневыми деталями HTTP[cite: 3373].
    * [cite_start]**Встроенное балансирование нагрузки**: При использовании с реестром сервисов (например, Eureka) Feign автоматически распределяет запросы между несколькими экземплярами целевого сервиса[cite: 3377].
    * [cite_start]**Поддержка резервирования (Fallback)**: Позволяет определить запасной класс-реализацию, который будет вызван, если удаленный сервис недоступен или произошла ошибка[cite: 3328].
