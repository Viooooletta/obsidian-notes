##  Лабораторная №2: Юнит-тестирование в Spring Boot с JUnit 5 и Mockito

Эта работа посвящена **юнит-тестированию** — технике тестирования, при которой **отдельные компоненты** (модули, классы, методы) программного приложения проверяются **изолированно**.

| Инструмент                   | Сущность и назначение                                                                                                                                                                   |
| :--------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **JUnit 5**                  | Популярный фреймворк для **тестирования Java**. Предоставляет аннотации (`@Test`, `@BeforeEach`) для определения тестовых методов и классов.                                            |
| **Mockito**                  | Фреймворк для создания **мок-объектов (заглушек)** зависимостей (например, репозитория или сервиса). Используется для **изоляции** тестируемого компонента от его реальных зависимостей |
| **AssertJ**                  | Библиотека, предоставляющая **выразительные утверждения** (`assertThat(...).isEqualTo(...)`) для более четкого и читаемого кода проверок ожидаемых результатов.                         |
| **Spring Boot Starter Test** | Зависимость, включающая в себя все основные библиотеки для тестирования Spring Boot: **JUnit**, **Mockito**, **Hamcrest**, **AssertJ**.                                                 |

### Основные аннотации и концепции

* **`@DataJpaTest`**: Используется для тестирования **JPA репозиториев**. Загружает только минимальный контекст Spring, связанный с базой данных (не загружает `@Service`, `@Controller` и т.д.).
* **`@WebMvcTest`**: Используется для тестирования **Spring MVC контроллеров**. Загружает только контекст, связанный с MVC, и часто используется с **MockMvc**.
* **MockMvc**: Класс, позволяющий выполнять **виртуальные HTTP-запросы** к контроллерам без запуска полноценного HTTP-сервера.
* **BDD-стиль Mockito**: Используется для настройки поведения мок-объектов:
    *`given()`: Настройка предварительного условия (что мок должен вернуть).
    * `verify()`: Проверка, что метод мок-объекта был вызван.
* **`@Rollback(true)`**: Указывает, что транзакция должна быть **откачена** после завершения тестового метода, чтобы не влиять на состояние базы данных.

Эта работа знакомит с инструментом для **управления миграциями баз данных**.

* **Flyway**: Универсальный инструмент с открытым исходным кодом для **миграции баз данных и управления схемами**.
* **Назначение**: Решает проблемы ручных миграций (несогласованность, ошибки), автоматизируя задачи и обеспечивая **версионный контроль** изменений схемы.
* **Принцип работы**: Flyway автоматически обнаруживает **миграционные скрипты** (обычно SQL-файлы, например, `V1__create_table.sql`) в определенной директории (`db/migration`) и применяет их к базе данных.
* **Таблица метаданных**: Flyway отслеживает все примененные миграции в специальной таблице `flyway_schema_history`. Это гарантирует, что каждый скрипт будет выполнен только один раз и в правильном порядке.
* **Интеграция**: Flyway бесшовно интегрируется со Spring Boot, запуская миграции автоматически при старте приложения.

##  Лабораторная №6: @FeignClient

Запуск проекта

- **Вкладка 2:** `http://localhost:8080/api/products/external/posts`
    
- **Вкладка 3:** `http://localhost:8080/api/products/external/posts/1`

**Feign Client** - это декларативный HTTP-клиент от Spring Cloud, который упрощает вызовы REST API других сервисов.

Эта работа посвящена **межсервисной коммуникации** в архитектуре микросервисов.

* **@FeignClient (Spring Cloud OpenFeign)**: Аннотация Spring, предназначенная для **декларативного** и упрощенного **взаимодействия между микросервисами** (клиент-серверная связь).
* **Назначение**: Абстрагирует уровень HTTP-клиента. Вместо написания шаблонного кода для HTTP-вызовов, разработчик просто определяет **Java-интерфейс**, аннотированный `@FeignClient`, а Spring автоматически генерирует его реализацию для выполнения REST-вызовов.
* **Ключевые преимущества**:
    * **Декларативный подход**: Вы просто описываете, какой сервис и метод вызвать, не занимаясь низкоуровневыми деталями HTTP.
    * **Встроенное балансирование нагрузки**: При использовании с реестром сервисов (например, Eureka) Feign автоматически распределяет запросы между несколькими экземплярами целевого сервиса.
    * **Поддержка резервирования (Fallback)**: Позволяет определить запасной класс-реализацию, который будет вызван, если удаленный сервис недоступен или произошла ошибка.
