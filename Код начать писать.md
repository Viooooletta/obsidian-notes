## 🛠️ План разработки программного средства

### ЭТАП 1: Настройка Окружения и База Данных (Backend Foundation)

**Технологии:** Java, Spring Boot, MySQL.

|**Шаг**|**Описание задачи**|**Требование ТЗ / Примечание**|
|---|---|---|
|**1.1**|**Настройка проекта Spring Boot**|Создание проекта, подключение зависимостей (Spring Web, Spring Data JPA, Spring Security, MySQL Driver).|
|**1.2**|**Проектирование схемы БД (MySQL)**|Разработка логической модели данных: **Заказы**, **Транспортные средства (ТС)**, **Склады**, **Рейсы/Маршруты**, **Пользователи**.|
|**1.3**|**Скрипт генерации БД**|Создание SQL-скрипта (`schema.sql` и `data.sql`) для инициализации таблиц и тестовых данных. _Обязательное требование приложения._|
|**1.4**|**Создание сущностей JPA**|Разработка Java-классов (`@Entity`) для каждой таблицы БД (User, Order, Vehicle, Route и т.д.).|
|**1.5**|**Создание Репозиториев (Spring Data JPA)**|Разработка интерфейсов для CRUD-операций с каждой сущностью (`...Repository`).|

### ЭТАП 2: Модуль Безопасности и Авторизации (Spring Security)

**Технологии:** Java, Spring Boot 3.0.5, Spring Security 6.0.2, JWT.

|**Шаг**|**Описание задачи**|**Требование ТЗ / Примечание**|
|---|---|---|
|**2.1**|**Настройка Spring Security**|Базовая конфигурация безопасности: отключение CSRF, настройка CORS, создание фильтров.|
|**2.2**|**Разработка сервиса Пользователей**|Реализация логики регистрации (`/register`) и авторизации (`/login`) с использованием ролей (`ADMIN`, `PLANNER`, `DRIVER`).|
|**2.3**|**Реализация JWT-аутентификации**|Создание утилит для генерации, валидации и извлечения данных из JWT-токенов.|
|**2.4**|**Настройка ролевого доступа**|Ограничение доступа к контроллерам/методам с помощью аннотаций (`@PreAuthorize("hasRole('ADMIN')")`), в соответствии с ролевой схемой.|

### ЭТАП 3: Разработка Серверной API и Базовой Логики (Backend Logic)

**Технологии:** Java, Spring Boot.

|**Шаг**|**Описание задачи**|**Требование ТЗ / Примечание**|
|---|---|---|
|**3.1**|**API для CRUD-операций со справочниками**|Создание REST-контроллеров и сервисов для управления **Транспортом**, **Складами** и **Пользователями** (доступно только `ADMIN`).|
|**3.2**|**API для управления Заказами**|Создание контроллеров для просмотра, добавления и редактирования Заказов (доступно `PLANNER`).|
|**3.3**|**API для Водителя**|Создание контроллеров для получения списка назначенных Рейсов и обновления статуса Доставки (доступно `DRIVER`).|

### ЭТАП 4: Реализация Ключевого Алгоритма Планирования

**Технологии:** Java (Собственный алгоритм).

|**Шаг**|**Описание задачи**|**Требование ТЗ / Примечание**|
|---|---|---|
|**4.1**|**Модели данных для алгоритма**|Создание вспомогательных классов для представления входных данных алгоритма (например, `DeliveryPoint`, `VehicleCapacity`).|
|**4.2**|**Разработка VRP-алгоритма**|Реализация логики **объемно-календарного планирования** (Variable Routing Problem - VRP). Алгоритм должен учитывать ограничения по объему, весу и временным окнам. _Ядро курсовой работы._|
|**4.3**|**Интеграция алгоритма в Сервис**|Создание `PlanningService` с методом `calculateOptimalRoutes()`, который принимает заказы и парк ТС, запускает алгоритм и возвращает список оптимизированных Рейсов/Маршрутов.|
|**4.4**|**API для запуска планирования**|Создание контроллера (`/api/planning/calculate`) для Логиста, который инициирует выполнение алгоритма.|
|**4.5**|**Сохранение результатов**|Логика сохранения сгенерированных Рейсов и Маршрутов в БД после завершения расчета.|
|**4.6**|**Листинг кода алгоритмов**|Выделение кода алгоритма для включения в **Приложения** пояснительной записки.|

### ЭТАП 5: Разработка Клиентской Части (Frontend)

**Технологии:** JavaScript/TypeScript, React.

|**Шаг**|**Описание задачи**|**Требование ТЗ / Примечание**|
|---|---|---|
|**5.1**|**Настройка проекта React**|Инициализация проекта, подключение маршрутизатора и базовых стилей.|
|**5.2**|**Компоненты Авторизации**|Создание страниц `/login` и `/register` и их интеграция с JWT API (Шаг 2.2).|
|**5.3**|**Роутинг и защита маршрутов**|Настройка маршрутизации на основе роли пользователя (защита путей, не допуск Водителя к панели Планирования).|
|**5.4**|**Панель Администратора (CRUD-справочники)**|Создание интерфейсов для управления ТС, Складами и Пользователями.|
|**5.5**|**Панель Логиста-планировщика**|Разработка основного интерфейса:<br><br>  <br><br>а) Таблица активных заказов.<br><br>  <br><br>б) Кнопка **"Запустить планирование"** (вызов API Шага 4.4).<br><br>  <br><br>в) Интерфейс для просмотра и ручной корректировки сгенерированных Рейсов/Маршрутов.|
|**5.6**|**Панель Водителя**|Создание интерфейса для просмотра назначенных Рейсов и кнопок для изменения статуса доставки.|
