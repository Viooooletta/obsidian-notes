Отлично — соберу для тебя практичный, конкретный план страниц (фронтенд/бэкенд) для курсовой по «Автоматизации объёмно-календарного планирования процесса доставки товаров логистического предприятия», чтобы покрыть требование ≥8 сущностей, 3NF и ≥12 функциональных сценариев (без учёта простых CRUD). Ниже — список сущностей + краткая нота о нормализации, затем — подробный план страниц, какими сущностями они оперируют, какие UI-компоненты нужны и какие «не-CRUD» варианты использования каждая страница покрывает.

# 1) Рекомендуемые сущности (≥8) — структура в 3NF

Коротко: каждая сущность содержит атомарные атрибуты, связи оформлены через FK в отдельные таблицы, повторяющиеся группы вынесены в отдельные таблицы.

1. **Customer (Клиент)** — id, name, contact_info_id (FK).
    
2. **ContactInfo** — id, phone, email, address_id (FK).
    
3. **Address** — id, street, city, postal_code, coordinates (lat,lng).
    
4. **Product (Товар)** — id, sku, name, weight, volume, dimensions.
    
5. **Order (Заказ клиента)** — id, customer_id (FK), order_date, status.
    
6. **OrderItem** — id, order_id (FK), product_id (FK), qty.
    
7. **Shipment (Отправка / партия для доставки)** — id, planned_date, actual_date, status, origin_address_id, dest_address_id.
    
8. **ShipmentItem** — id, shipment_id (FK), order_item_id (FK), qty.
    
9. **Vehicle** — id, reg_number, capacity_weight, capacity_volume, type.
    
10. **Driver** — id, name, license, contact_info_id (FK).
    
11. **Route (Маршрут/Рейс)** — id, vehicle_id (FK), driver_id (FK), date, planned_distance, cost_estimate.
    
12. **RouteStop (Остановка в маршруте)** — id, route_id (FK), sequence_number, address_id (FK), estimated_arrival, service_time.
    
13. **CalendarPlan / PlanVersion** — id, created_by, valid_from, valid_to, description (версии планов).
    
14. **AuditLog / Event** — id, entity, action, user_id, timestamp, details.
    

(Это 14 сущностей; связи Order→OrderItem, Shipment→ShipmentItem, Route→RouteStop обеспечивают 3NF: повторяющиеся/мультиэлементы вынесены в отдельные таблицы.)

# 2) Список страниц (UI) — что реализовать и зачем

Для каждой страницы укажу: цель, задействованные сущности, ключевые компоненты UI, роли (Admin / Planner / Dispatcher / Driver / Viewer), и какие НЕ-CRUD use-cases покрываются.

---

## 1. Страница входа / регистрация (Login / Auth)

- Сущности: User (пользователь/роли), AuditLog (аутентификация).
    
- UI: форма логина, 2FA (опционально), забыли пароль.
    
- Роли: все.
    
- Use-case: аутентификация и авторизация (не-CRUD).
    

---

## 2. Дашборд планировщика (Planner Dashboard)

- Сущности: CalendarPlan, Shipment, Route, Vehicle, Driver, Order (агрегаты).
    
- UI: KPI (кол-во планов, отправок сегодня), график загрузки транспорта, предупреждения, quick actions.
    
- Роли: Planner, Manager.
    
- Use-cases: обзор текущих планов; быстрый переход к оптимизации/перепланированию; мониторинг перерасхода/отставаний.
    

---

## 3. Управление сущностями (CRUD панели)

(Отдельные страницы/модальные): Клиенты, Заказы, Товары, Адреса, Транспорт, Водители, Пользователи.

- Сущности: Customer, Order, Product, Address, Vehicle, Driver, User.
    
- UI: таблицы с фильтрами, импорт/экспорт CSV, привязки.
    
- Роли: Admin.
    
- Примечание: CRUD страницы нужны, но в подсчёт 12 use-cases не входят.
    

---

## 4. Страница составления объёмно-календарного плана (Planner Workspace)

- Сущности: Order, OrderItem, Shipment, ShipmentItem, CalendarPlan, Address.
    
- UI: drag&drop панель (перетаскивание заказов в отправки), календарь/таблица; валидация вместимости.
    
- Роли: Planner.
    
- Use-cases (не-CRUD):
    
    1. Формирование планов отправок из наборов заказов (агрегация по дате/региону).
        
    2. Автоматическое разбивание больших заказов на несколько партий (split shipments).
        
    3. Валидация вместимости по весу/объёму при планировании.
        

---

## 5. Оптимизация маршрутов (Route Optimizer)

- Сущности: Shipment, Route, RouteStop, Vehicle, Driver, Address (координаты).
    
- UI: форма параметров оптимизации (приоритет: время/стоимость/кол-во машин), кнопка «Оптимизировать», таблица маршрутов, карта (если интегрировать).
    
- Роли: Planner, Dispatcher.
    
- Use-cases:  
    4. Построение оптимальных маршрутов (multi-stop VRP-like) с учётом вместимости.  
    5. Перераспределение отправлений между транспортными средствами (reassignment).
    

---

## 6. Назначение транспорта и водителей (Assignment)

- Сущности: Route, Vehicle, Driver, CalendarPlan.
    
- UI: drag&drop назначение vehicle/driver на маршрут; проверка допустимости (лицензии, доступность).
    
- Роли: Dispatcher, Planner.
    
- Use-cases:  
    6. Автоматическое/ручное распределение водителей и автомобилей по маршрутам с учётом ограничений.  
    7. Проверка конфликтов расписания и предупреждения о перегрузке.
    

---

## 7. Календарь / Gantt-вид плана (Calendar / Timeline)

- Сущности: CalendarPlan, Route, RouteStop, Shipment.
    
- UI: интерактивный календарь/Gantt: перетаскивание рейсов по времени, zoom, фильтрация по региону/vehicle.
    
- Роли: Planner, Dispatcher, Manager.
    
- Use-cases:  
    8. Визуальное планирование во времени (перенос рейсов, пересчёт ETA).  
    9. Создание альтернативных версий плана (PlanVersion).
    

---

## 8. Отслеживание статуса в реальном времени (Tracking / Live)

- Сущности: Route, RouteStop, Shipment, Driver (текущее положение), Event/AuditLog.
    
- UI: карта с текущим положением, список отклонений, статус по отправкам.
    
- Роли: Dispatcher, Manager.
    
- Use-cases:  
    10. Мониторинг исполнения (факт прибытия/отправки, отклонения от ETА).  
    11. Автоматическое переназначение при срывах (fallback flows).
    

---

## 9. Страница редактирования и подтверждения документов (Manifests / Delivery Notes)

- Сущности: Shipment, ShipmentItem, Order, Customer.
    
- UI: PDF-генерация/печать, подпись водителя (электронная), загрузка фото подтверждения.
    
- Роли: Driver (через мобильный интерфейс), Dispatcher.
    
- Use-cases:  
    12. Генерация и подписание накладных/манифестов, привязка фото/подписи как доказательства доставки.
    

---

## 10. Перепланирование / Rescheduling (инструмент)

- Сущности: Route, Shipment, CalendarPlan, PlanVersion.
    
- UI: сценарии «если X задерживается, как перепланировать»: one-click reschedule, view impact.
    
- Роли: Planner, Dispatcher.
    
- Use-cases:  
    13. Автоматическое перепланирование при задержке или отказе транспорта (what-if анализ).
    

---

## 11. Стоимостной расчёт и расчёт загрузки (Cost & Load Calculator)

- Сущности: Vehicle, Route, Shipment, Product (вес/объём), CostRates (новая таблица).
    
- UI: калькулятор стоимости рейса, прогноз затрат, периодические тарифы, отображение загрузки % по машине.
    
- Роли: Manager, Planner.
    
- Use-cases:  
    14. Расчёт себестоимости рейса/партии и сравнение альтернативных планов.
    

---

## 12. Отчёты и аналитика (Reports)

- Сущности: Route, Shipment, Driver, Vehicle, Order, CalendarPlan.
    
- UI: формы генерации отчётов (по периоду/региону/водителю), экспорт в PDF/Excel, диаграммы нагрузки и KPI.
    
- Роли: Manager, Admin.
    
- Use-cases:  
    15. Генерация отчётов эффективности, SLA, utilization.
    

---

## 13. Уведомления / Коммуникация (Notifications)

- Сущности: Event, User, Shipment.
    
- UI: настройка правил уведомлений (SMS/Email/in-app), лог уведомлений, шаблоны.
    
- Роли: все.
    
- Use-cases:  
    16. Автоматические уведомления клиентам о доставке (ETA), оповещения диспетчеру при отклонениях.
    

---

## 14. История изменений / аудит (Audit)

- Сущности: AuditLog, User, Route, Shipment.
    
- UI: журнал действий, фильтры, откат версий планов (если нужно).
    
- Роли: Admin, Manager.
    
- Use-cases:  
    17. Отслеживание всех изменений в плане и восстановление версии.
    

---

## 15. Профиль водителя / мобильный интерфейс (Driver App)

- Сущности: Driver, Route, RouteStop, ShipmentItem, Event.
    
- UI: список сегодняшних маршрутов, подтверждение остановок, загрузка фото, навигация.
    
- Роли: Driver.
    
- Use-cases:  
    18. Подтверждение выполнения остановки, отправка фото/подписей, связь с диспетчером.
    

---

# 3) Как страницы покрывают ≥12 не-CRUD use-cases (сводка)

Перечисляю 12+ конкретных сценариев, которые обязательно реализовать (и где они выполняются):

3. Валидация вместимости по вес/объёму (Planner Workspace + Assignment).
    
4. Оптимизация маршрутов (Route Optimizer).
    
5. Автоматическое перераспределение отправлений между машинами (Route Optimizer).
    
6. Автоматическое/ручное назначение водителей и транспорта (Assignment).
    
7. Проверка конфликтов расписания (Assignment + Calendar).
    
8. Визуальное планирование (Calendar / Gantt).
    
9. Создание и управление версиями плана (Calendar / Planner Workspace).
    
10. Мониторинг исполнения/реальное отслеживание (Tracking).
    
11. Автоматическое перепланирование при сбоях (Rescheduling tool).
    
12. Генерация и подписание манифестов/накладных (Manifests).
    
13. Расчёт стоимости и сравнение вариантов (Cost Calculator).
    
14. Отчёты эффективности и экспорт (Reports).
    
15. Уведомления клиентам и диспетчеру (Notifications).
    
16. Подтверждение доставки водителем (Driver App).

# 4) Технические заметки (endpoints / UX)

- REST endpoints: `/api/plans`, `/api/shipments`, `/api/routes/optimize`, `/api/routes/{id}/assign`, `/api/tracking`, `/api/reports`, `/api/notifications`.
    
- Авторизация: Spring Security — роли `ROLE_ADMIN`, `ROLE_MANAGER`, `ROLE_PLANNER`, `ROLE_DISPATCHER`, `ROLE_DRIVER`, `ROLE_VIEWER`.
    
- Импорт/экспорт CSV/Excel для заказов и товаров.
    
- Для маршрутов: интеграция с алгоритмом оптимизации (можно начать простым эвристическим алгоритмом: кластеризация по региону + nearest neighbour; при желании интегрировать внешние API).
    
- Карты: можно подключить Leaflet/OpenStreetMap (не платно) — отдельная страница Map View.
    
- Документы: PDF-генерация через iText или OpenPDF.
    

# 5) Приоритет реализации (рекомендуемый порядок)

1. Auth + CRUD (Users, Customers, Products, Orders, Vehicles, Drivers).
    
2. Planner Workspace + Calendar (основа для планирования).
    
3. Route Optimizer + Assignment.
    
4. Tracking + Driver App (минимально: интерфейс подтверждения).
    
5. Manifests + PDF.
    
6. Reports + Notifications + Audit.
